# Kufar Telegram Notifier

Бот для самостоятельного хостинга, который следит за поисками на [Kufar](https://kufar.by) и публикует новые объявления в Telegram-чат или тему форума. Каждый поиск планируется независимо, отправка в Telegram идёт через отдельную очередь, а для видеокарт добавляется рыночная цена.

Уведомления пишутся на русском языке и отправляются в HTML с фото или медиагруппой, если они есть в объявлении.

> **Дисклеймер:** Проект предназначен только для ознакомительных и образовательных целей. Он не связан с Kufar и не одобрен Kufar. Используйте его на свой страх и риск и соблюдайте условия Kufar и применимое законодательство.

## Требования

- Компилятор C++20 (`g++` или `clang++`)
- CMake 3.16+
- Заголовочные файлы libcurl, spdlog, Boost и nlohmann-json
- Git и доступ к сети при первой конфигурации (tgbot-cpp скачивается автоматически)
- Docker и Docker Compose (необязательно)

## Сборка

### Linux

Debian / Ubuntu:

```sh
sudo apt update
sudo apt install -y build-essential cmake git libcurl4-openssl-dev libspdlog-dev libboost-dev nlohmann-json3-dev
```

Fedora:

```sh
sudo dnf install -y gcc-c++ make cmake git libcurl-devel spdlog-devel boost-devel json-devel
```

Arch Linux:

```sh
sudo pacman -S --needed base-devel cmake git curl spdlog boost nlohmann-json
```

### macOS

```sh
xcode-select --install
brew install cmake boost nlohmann-json curl spdlog
```

Если CMake не находит пакеты Homebrew, добавьте `-DCMAKE_PREFIX_PATH="$(brew --prefix)"` в команду конфигурации.

### Компиляция

```sh
git clone https://github.com/Am80286/Kufar-Telegram-Notifier-fork.git
cd Kufar-Telegram-Notifier-fork
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

Исполняемый файл: `build/bin/Kufar-Telegram-Notifier`. При первой конфигурации tgbot-cpp v1.13 скачивается в `build/_deps`; при следующих сборках используется уже скачанная копия. Если исходники уже есть, передайте `-DFETCHCONTENT_SOURCE_DIR_TGBOT_CPP=/путь/к/tgbot-cpp`.

### Тесты

Запустите `ctest --output-on-failure` из каталога `build`. Чтобы не собирать тесты, укажите `-DBUILD_TESTING=OFF` при конфигурации.

## Docker

Контейнер работает от UID/GID `1000`, хранит конфигурацию и кеш в `/data` и пишет лог в вывод контейнера.

```sh
mkdir -p data
cp kufar-configuration.json data/kufar-configuration.json
# отредактируйте data/kufar-configuration.json

docker compose up -d --build
docker compose logs -f
docker compose down
```

Каталог `data` должен быть доступен на запись пользователю с UID `1000`, потому что бот перезаписывает конфигурацию и кеш. Compose-файл делает остальную файловую систему доступной только для чтения, сбрасывает capabilities, включает `no-new-privileges` и перезапускает контейнер, пока его не остановят.

Без Compose: `docker build -t kufar-telegram-notifier .`, затем `docker run --rm -v "$PWD/data:/data" kufar-telegram-notifier`.

Образ запускается с параметрами `--config /data/kufar-configuration.json --cache /data/cached-data.json --no-log`.

## Запуск

Запускайте бота из каталога, доступного на запись: по умолчанию там создаются файлы кеша и лога.

```sh
./build/bin/Kufar-Telegram-Notifier
```

При запуске бот проверяет токен и доступ к чату `chat-id`; при ошибке он пишет её в лог и завершается. Остановите его через `Ctrl+C` или `SIGTERM`; при корректной остановке кеш сохраняется.

Опрос и отправка в Telegram работают независимо. Найденные объявления ставятся в очередь и отправляются примерно по 20 сообщений в минуту; временные ошибки отправки повторяются автоматически, а объявление с неудачной отправкой освобождается для следующего опроса.

### Параметры командной строки

| Параметр | Описание |
| --- | --- |
| `-c`, `--config <файл>` | Файл конфигурации. По умолчанию: `kufar-configuration.json`. |
| `--cache <файл>` | Файл кеша. По умолчанию: `cached-data.json`. Создаётся при отсутствии. |
| `-l`, `--log <файл>` | Файл лога. По умолчанию: `kufar-notifier.log`. |
| `--no-log` | Писать лог только в консоль. |
| `--log-level <уровень>` | `trace`, `debug`, `info`, `warn`, `error` или `critical`. По умолчанию: `info`. |
| `-V`, `--version` | Показать версию и выйти. |
| `-h`, `--help` | Показать справку и выйти. |

## Команды Telegram

Бот использует long polling, поэтому публичный IP и webhook не нужны. Ответ приходит в тот же чат и тему. `/add` и `/del` игнорируются вне настроенного чата.

| Команда | Описание |
| --- | --- |
| `/start` | Показать состояние бота. |
| `/add <ссылка> [метка]` | Добавить поиск по ссылке на результаты Kufar. |
| `/list` | Показать поиски текущей темы. |
| `/del <N>` | Удалить поиск с номером `N` из текущей темы. |

`/add` принимает `https`-ссылки на страницы поиска на `www.kufar.by`, `auto.kufar.by` и `re.kufar.by`; путь должен быть `/l` или начинаться с `/l/`. Страница загружается в фоне, запрос привязывается к текущей теме, а необязательная метка (до 64 символов) сохраняется для `/list`. Неизвестные фильтры вызывают ошибку. Параметр `size` веб-интерфейса игнорируется, потому что опрос использует свой размер страницы.

`/list` нумерует поиски в пределах темы, `/del N` удаляет поиск с этим номером из текущей темы. `/add` и `/del` перезаписывают файл конфигурации.

## Конфигурация

По умолчанию бот читает `kufar-configuration.json`. Файл содержит разделы `telegram`, `queries` и необязательные `scheduler` и `kufar`.

Минимальный пример:

```json
{
    "telegram": {
        "bot-token": "1111111111:AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA",
        "chat-id": -1001234567890
    },
    "queries": [
        {
            "tag": "iPhone",
            "label": "Телефоны в Минске",
            "message-thread-id": 42,
            "only-title-search": true,
            "poll-interval-seconds": 120,
            "region": 7
        }
    ],
    "scheduler": {
        "default-interval-seconds": 60,
        "min-interval-seconds": 60,
        "max-interval-seconds": 300,
        "jitter-percent": 15
    },
    "kufar": {
        "requests-per-second": 4,
        "burst": 4,
        "cooldown-seconds": 30
    }
}
```

### Telegram

Создайте бота через [@BotFather](https://t.me/BotFather) и добавьте его в нужный чат. Для отдельных тем включите **Темы** в супергруппе и дайте боту право писать туда.

| Ключ | Обязателен | Описание |
| --- | --- | --- |
| `bot-token` | Да | Токен от BotFather. |
| `chat-id` | Да | ID целевого чата. ID групп и супергрупп отрицательные. |

### Запросы

Каждый объект в `queries` — одна лента поиска. Все поля необязательны, но запрос без фильтров вернёт результаты Kufar по умолчанию.

| Ключ | Тип | Описание |
| --- | --- | --- |
| `id` | целое число | Внутренний ID запроса. Управляется ботом; не редактируйте. |
| `tag` | строка | Поисковый текст. Также показывается как хештег, если в нём нет пробелов. |
| `label` | строка | Название для `/list` и логов, до 64 символов. |
| `message-thread-id` | целое число | ID темы для этого запроса (должен быть положительным). Если не указан, публикация в основную тему. |
| `poll-interval-seconds` | целое число | Желаемый интервал опроса этого запроса (должен быть положительным). |
| `only-title-search` | boolean | Искать только в заголовках. |
| `price` | объект | Диапазон цен в целых BYN. |
| `price.min` | целое число | Минимальная цена. |
| `price.max` | целое число | Максимальная цена. |
| `language` | строка | Язык поиска, например `ru`. |
| `currency` | строка | Код валюты, передаваемый Kufar. В уведомлениях цена в BYN. |
| `condition` | целое число | `1` — б/у, `2` — новое. |
| `seller-type` | целое число | `0` — частное лицо, `1` — компания. |
| `kufar-delivery-required` | boolean | Только объявления с Kufar Доставкой. |
| `kufar-payment-required` | boolean | Только объявления с Kufar Оплатой. |
| `kufar-halva-required` | boolean | Только объявления с Kufar Халвой. |
| `only-with-photos` | boolean | Только объявления с фото. |
| `only-with-videos` | boolean | Только объявления с видео. |
| `only-with-exchange-available` | boolean | Только объявления с обменом. |
| `sort-type` | целое число | Сортировка по цене: `1` — по убыванию, `2` — по возрастанию. |
| `category` | целое число | ID основной категории. |
| `sub-category` | целое число | ID подкатегории. |
| `computer-component-type` | целое число | Тип комплектующих для подкатегории `16010`. |
| `region` | целое число | ID региона. |
| `areas` | массив целых чисел | ID районов и городов. |
| `source-url` | строка | Ссылка Kufar, из которой импортирован запрос. Только для информации. |

Логические фильтры передаются только при значении `true`. Удалённое поле `limit` игнорируется.

Без `sort-type` поиски опрашиваются от новых объявлений к старым. Обычный опрос читает до 10 страниц по 200 объявлений и останавливается после 10-минутного окна перекрытия ниже предыдущей позиции. Если достигнут лимит страниц, более старые объявления из этого окна пропускаются с предупреждением. При холодном старте (новый запрос или нет сохранённой позиции) публикуются только 10 самых новых объявлений. Запросы с `sort-type` просматривают только 10 самых новых записей текущей страницы.

### Планировщик

| Ключ | По умолчанию | Описание |
| --- | --- | --- |
| `default-interval-seconds` | `60` | Начальный интервал для запросов без `poll-interval-seconds`. |
| `min-interval-seconds` | как default | Минимальный интервал. |
| `max-interval-seconds` | `max(300, min)` | Максимальный интервал после увеличения при простоях. |
| `jitter-percent` | `15` | Случайное отклонение интервала в пределах ± указанного процента. |

Каждый запрос планируется независимо. Базовый интервал — это большее из значений `poll-interval-seconds` (или `default-interval-seconds`) и `min-interval-seconds`. Интервал начинается с этого значения и сбрасывается к нему при постановке новых объявлений в очередь. После опросов без новых объявлений он растёт в 1,5 раза до максимума. `poll-interval-seconds` задаёт собственный интервал запроса.

Старый раздел `delays` устарел. `delays.query` игнорируется. Если `scheduler` отсутствует, `delays.loop` используется как запасной интервал.

### Ограничения запросов Kufar

Все HTTP-запросы к Kufar используют общий лимитер и паузу.

| Ключ | По умолчанию | Описание |
| --- | --- | --- |
| `requests-per-second` | `4` | Устойчивая частота запросов. |
| `burst` | `4` | Максимальный размер всплеска. |
| `cooldown-seconds` | `30` | Базовая пауза после HTTP 429, 5xx или ошибки транспорта. |

Повторные ошибки 5xx и транспорта увеличивают паузу экспоненциально до 5 минут. `Retry-After` учитывается.

### Темы

Чтобы узнать ID темы, откройте ссылку на сообщение внутри неё:

```text
https://t.me/c/1234567890/42/123
```

Здесь `42` — ID темы. Кеш ведётся отдельно для каждой темы, поэтому одно объявление отправляется в тему только один раз, даже если его нашли несколько запросов.

## Файл кеша

`cached-data.json` хранит ID отправленных объявлений по темам и позицию опроса каждого запроса. Файл создаётся автоматически; не редактируйте его во время работы бота.

```json
{
    "version": 3,
    "buckets": {
        "default": [123456789],
        "42": [123456789, 987654321]
    },
    "frontiers": {
        "1": {
            "frontier": 1732123456,
            "suppress-before": 1732119856
        }
    }
}
```

`default` — основная тема, остальные ключи — ID тем. `frontiers` позволяет продолжить опрос с предыдущей позиции после перезапуска, а не начинать как при холодном старте. Кеш версии 2 загружается с пустой позицией опроса; старый кеш в виде плоского массива игнорируется.

Объявление резервируется перед отправкой и помечается отправленным только после подтверждения Telegram. Неудачные отправки повторяются при следующем опросе. Кеш записывается атомарно не чаще раза в две минуты и при корректной остановке; после аварийного завершения недавние объявления могут быть отправлены повторно. Удаление запроса командой `/del` не удаляет его записи из кеша.

## Оценка цены

Для видеокарт уведомление показывает медиану рынка и то, насколько цена ниже или выше неё. Эта фича еще в разработке, отсюда ограничение на только видеокарты.

Оцениваются только объявления подкатегории `16010` с типом комплектующих `11`. Бот определяет модель видеокарты и объём памяти по структурированным параметрам или заголовку; ноутбучные видеокарты считаются отдельным вариантом. Неисправные объявления и объявления на запчасти, сборки, объявления с моделью процессора, неоднозначные или конфликтующие модели, неоднозначная память и объявления без распознаваемой модели пропускаются.

Базы собираются в фоне по всей подкатегории комплектующих без учёта фильтров запроса. Цены за пределами 1,5 межквартильного размаха отбрасываются, используется медиана оставшихся. Для конкретной модели и варианта нужно не менее 10 цен; иначе для базовой модели нужно не менее 5. Если данных нет, объявление отправляется без оценки.

Снимки хранятся в памяти, используются 6 часов и обновляются в фоне; после неудачного обновления повторная попытка через 5 минут. Обрезанный обход всё равно публикует частичную базу. Если снимка ещё нет, объявление отправляется сразу, а сообщение редактируется после завершения обхода.

## Логирование

По умолчанию бот пишет `kufar-notifier.log` и одновременно выводит лог в консоль. Используйте `--no-log`, `--log <файл>` и `--log-level <уровень>`, чтобы изменить это поведение.
