# Kufar Telegram Notifier

Небольшой бот для самостоятельного хостинга, который следит за новыми объявлениями на [Kufar](https://kufar.by) и публикует их в Telegram-чате. Поисковые запросы задаются в JSON-файле; бот опрашивает Kufar с настраиваемым интервалом и отправляет каждое объявление, которое ещё не видел. Каждый запрос может публиковаться в отдельной теме (thread) супергруппы Telegram, поэтому один бот может вести несколько независимых лент.

> **Дисклеймер:** Проект предназначен исключительно для ознакомительных и образовательных целей. Он не связан с Kufar и не одобрен Kufar. Используйте его на свой страх и риск и соблюдайте условия использования Kufar и применимое законодательство. Если вы являетесь представителем Kufar и у вас есть претензии к проекту, пожалуйста, создайте Issue в этом репозитории.

## Как это работает

1. Бот читает `kufar-configuration.json` и выполняет каждый запрос из `queries` через поисковый API Kufar.
2. Новые объявления отправляются в Telegram-чат. Если у запроса указан `message-thread-id`, объявления публикуются в эту тему; иначе они попадают в основную тему (General) чата.
3. ID отправленных объявлений сохраняются в `cached-data.json` отдельно для каждой темы, поэтому одно и то же объявление не публикуется дважды.
4. После выполнения всех запросов бот ждёт заданную задержку и начинает заново. Он работает в foreground до остановки.

Тексты сообщений, отправляемых ботом, сейчас написаны на русском языке.

## Требования

- Компилятор C++17 (`g++` или `clang++`)
- CMake 3.5 или новее
- Заголовочные файлы libcurl
- Заголовочные файлы spdlog
- Git (нужен только для клонирования репозитория)

## Сборка в Linux

Установите зависимости через пакетный менеджер вашего дистрибутива.

Debian / Ubuntu:

```sh
sudo apt update
sudo apt install -y build-essential cmake git libcurl4-openssl-dev libspdlog-dev
```

Fedora:

```sh
sudo dnf install -y gcc-c++ make cmake git libcurl-devel spdlog-devel
```

Arch Linux:

```sh
sudo pacman -S --needed base-devel cmake git curl spdlog
```

Затем склонируйте репозиторий и соберите проект:

```sh
git clone https://github.com/Am80286/Kufar-Telegram-Notifier-fork.git
cd Kufar-Telegram-Notifier-fork
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

Исполняемый файл появится в `build/bin/Kufar-Telegram-Notifier`.

## Сборка в macOS

Нужен только инструментарий командной строки; отдельного Xcode-проекта и шагов в IDE нет.

```sh
xcode-select --install
brew install cmake curl spdlog
```

Если Homebrew ещё не установлен, следуйте инструкциям на [brew.sh](https://brew.sh).

Затем склонируйте репозиторий и соберите проект:

```sh
git clone https://github.com/Am80286/Kufar-Telegram-Notifier-fork.git
cd Kufar-Telegram-Notifier-fork
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

Исполняемый файл появится в `build/bin/Kufar-Telegram-Notifier`.

Если CMake не находит libcurl или spdlog из Homebrew, укажите префикс Homebrew явно:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="$(brew --prefix)"
cmake --build build --parallel
```

## Запуск

Сборка даёт один исполняемый файл и ничего не устанавливает в систему. Запускайте его из каталога, в который у пользователя есть право записи: по умолчанию файлы кеша и лога создаются в текущем рабочем каталоге.

```sh
./build/bin/Kufar-Telegram-Notifier
```

Программа работает в foreground. Остановите её сочетанием `Ctrl+C`. Чтобы бот продолжал работать после закрытия терминала, используйте менеджер процессов, например systemd, tmux или screen.

### Параметры командной строки

| Параметр | Описание |
| --- | --- |
| `-c`, `--config <файл>` | Путь к файлу конфигурации. По умолчанию: `kufar-configuration.json` в текущем каталоге. |
| `--cache <файл>` | Путь к файлу кеша. По умолчанию: `cached-data.json` в текущем каталоге. Создаётся автоматически при отсутствии. |
| `-l`, `--log <файл>` | Путь к файлу лога. По умолчанию: `kufar-notifier.log` в текущем каталоге. |
| `--no-log` | Не записывать лог в файл, выводить только в консоль. |
| `--log-level <уровень>` | Уровень логирования: `trace`, `debug`, `info`, `warn`, `error` или `critical`. По умолчанию: `info`. |
| `-V`, `--version` | Показать версию программы и выйти. |
| `-h`, `--help` | Показать справку и выйти. |

Примеры:

```sh
# Использовать конфигурацию, кеш и лог из текущего каталога
./build/bin/Kufar-Telegram-Notifier

# Использовать файлы в другом расположении
./build/bin/Kufar-Telegram-Notifier \
  --config /etc/kufar-notifier/kufar-configuration.json \
  --cache /var/lib/kufar-notifier/cached-data.json \
  --log /var/log/kufar-notifier.log

# Логировать только в консоль, с отладочным выводом
./build/bin/Kufar-Telegram-Notifier --no-log --log-level debug
```

## Конфигурация

Бот читает JSON-файл `kufar-configuration.json` (по умолчанию). Полный пример находится в корне репозитория. Файл состоит из трёх разделов верхнего уровня: `telegram`, `queries` и `delays`.

Минимальный пример:

```json
{
    "telegram": {
        "bot-token": "1111111111:AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA",
        "chat-id": -1001234567890
    },
    "queries": [
        {
            "tag": "iPhone",
            "message-thread-id": 42,
            "only-title-search": true,
            "limit": 10
        },
        {
            "tag": "велосипед",
            "message-thread-id": 43,
            "price": {
                "min": 100,
                "max": 800
            },
            "region": 7
        }
    ],
    "delays": {
        "query": 10,
        "loop": 1800
    }
}
```

### Настройки Telegram

Перед настройкой файла создайте бота через [@BotFather](https://t.me/BotFather) и добавьте его в нужный чат.

| Ключ | Обязателен | Описание |
| --- | --- | --- |
| `bot-token` | Да | Токен, выданный BotFather. |
| `chat-id` | Да | ID чата, в который отправляются объявления. ID групп и супергрупп отрицательные, например `-1001234567890`. |

Чтобы отправлять объявления в отдельные темы, чат должен быть супергруппой с включённым режимом **Темы** (Topics / Forum), а у бота должно быть право отправлять туда сообщения. Добавьте бота в супергруппу и выдайте ему необходимые права администратора.

ID чата можно получить через Telegram Bot API (`getUpdates`) или с помощью любого инструмента для просмотра ID чатов. Для групп значение должно включать знак минуса.

### Настройки запросов

Каждый объект в `queries` описывает одну ленту поиска. Все поля запроса необязательны, но запрос вообще без фильтров просто вернёт результаты Kufar по умолчанию.

| Ключ | Тип | Описание |
| --- | --- | --- |
| `tag` | строка | Поисковый текст. Также используется как `#хештег` в начале сообщения Telegram. |
| `message-thread-id` | целое число | ID темы в супергруппе, куда публикуются объявления этого запроса. Должен быть положительным. Если не указан, объявления идут в основную тему (General). |
| `only-title-search` | boolean | Искать только в заголовках объявлений. |
| `price` | объект | Диапазон цен с необязательными значениями `min` и `max` в целых BYN. |
| `price.min` | целое число | Минимальная цена. |
| `price.max` | целое число | Максимальная цена. |
| `language` | строка | Код языка поиска, например `ru`. |
| `limit` | целое число | Максимальное количество объявлений за один запрос. Если не указано, используется значение Kufar по умолчанию. |
| `currency` | строка | Код валюты, передаваемый в API Kufar. В примере из репозитория используется `BYR`. В уведомлениях цена всегда отображается в BYN. |
| `condition` | целое число | Состояние товара: `1` — б/у, `2` — новое. |
| `seller-type` | целое число | Тип продавца: `0` — частное лицо, `1` — компания. |
| `kufar-delivery-required` | boolean | Только объявления с Kufar Доставкой. |
| `kufar-payment-required` | boolean | Только объявления с Kufar Оплатой. |
| `kufar-halva-required` | boolean | Только объявления с рассрочкой Kufar Халва. |
| `only-with-photos` | boolean | Только объявления с фото. |
| `only-with-videos` | boolean | Только объявления с видео. |
| `only-with-exchange-available` | boolean | Только объявления с возможностью обмена. |
| `sort-type` | целое число | Сортировка по цене: `1` — по убыванию, `2` — по возрастанию. |
| `category` | целое число | ID основной категории. См. таблицу категорий ниже. |
| `sub-category` | целое число | ID подкатегории. Полный список см. в `include/kufar.hpp`. |
| `region` | целое число | ID региона. См. таблицу регионов ниже. |
| `areas` | массив целых чисел | ID районов и городов для фильтрации. Полный список см. в `include/kufar.hpp`. |

Логические фильтры передаются в Kufar только при значении `true`. Значение `false` эквивалентно отсутствию параметра.

### Темы и message threads

Каждый запрос может публиковаться в отдельной теме. Чтобы узнать ID темы, откройте её в Telegram и посмотрите ссылку на любое сообщение внутри:

```text
https://t.me/c/1234567890/42/123
```

В этом примере `1234567890` — внутренний ID чата (полный ID чата в конфигурации будет `-1001234567890`), а `42` — ID темы, поэтому в конфигурации нужно указать `"message-thread-id": 42`.

Кеш ведётся отдельно для каждой темы, а не для каждого запроса. Если два запроса публикуются в одну тему, объявление будет отправлено в неё только один раз. Одно и то же объявление всё равно может быть отправлено в другую тему. Если удалить тему и создать новую, у неё будет новый ID, и история для неё начнётся заново.

### Задержки

| Ключ | Тип | Описание |
| --- | --- | --- |
| `delays.query` | целое число | Задержка в секундах после каждого запроса перед запуском следующего. |
| `delays.loop` | целое число | Задержка в секундах после последнего запроса перед новым проходом. |

Если весь раздел `delays` отсутствует, используются значения по умолчанию: `5` секунд между запросами и `30` секунд между проходами. Если раздел присутствует, оба поля `query` и `loop` обязательны.

## Файл кеша

`cached-data.json` хранит ID объявлений, которые уже были отправлены, сгруппированные по темам. Файл создаётся автоматически; не редактируйте его, пока бот работает. Структура файла:

```json
{
    "version": 2,
    "buckets": {
        "default": [123456789],
        "42": [123456789, 987654321]
    }
}
```

- `default` — объявления, отправленные в основную тему (запросы без `message-thread-id`).
- `"42"` — объявления, отправленные в тему с ID 42.

Объявление попадает в кеш только после того, как Telegram подтвердил отправку. Если отправка не удалась, бот запишет ошибку в лог и повторит попытку при следующем опросе.

Чтобы бот забыл, что уже отправлял, остановите его, удалите `cached-data.json` и запустите снова. Новый пустой кеш будет создан автоматически. Старые форматы кеша не переносятся: если найден старый кеш в виде плоского массива, он игнорируется с предупреждением, и отслеживание начинается заново.

## Логирование

По умолчанию бот пишет лог в `kufar-notifier.log` в текущем рабочем каталоге и одновременно выводит его в консоль. Используйте `--no-log`, чтобы отключить запись в файл, `--log <файл>`, чтобы выбрать другой путь, и `--log-level <уровень>`, чтобы изменить подробность лога.
